# 키워드 시장조사 (네이버 + 구글)

로담한의원(`_context/brand.md` 참고)의 특정 키워드에 대한 온라인 노출 현황을
네이버와 구글 양쪽에서 조사하고, 경쟁사 대비 부족한 점을 도출한다.

키워드가 주어지지 않았다면 먼저 사용자에게 물어본다.

## 진행 순서

### 0. 브랜드 컨텍스트 확인
`_context/brand.md`를 읽어 회사 기본 정보, 실수치, 타겟 고객, 자사 제품을 파악한다.
분석 시 이 파일의 사실만 근거로 사용하고, 확인 안 된 성과는 지어내지 않는다.

### 1. 네이버 조사 (병렬 실행)
네이버 검색 도구를 사용한다. 두 가지 소스가 있을 수 있음 — `ToolSearch`로
`naver search blog cafe kin datalab` 검색해서 어느 쪽이 로드되는지 확인:
- `mcp__naver-search__*` (프로젝트 `.mcp.json`에 등록된 자체 서버, 우선 사용)
- `mcp__claude_ai_PlayMCP__NaverSearch-*` (계정 커넥터, 위가 끊겼을 때 대체)

- `search_blog` (display 20, sort sim) — 블로그 후기/콘텐츠 상위 노출 현황
- `search_cafearticle` (display 20, sort sim) — 커뮤니티/카페 논의 현황
- `search_kin` (display 20, sort sim) — 지식iN Q&A 노출 현황 (구매 직전 채널이라 중요)
- `search_local` (display 5, sort comment) — 플레이스/지역업체 상위 노출
- `datalab_search` — 최근 1년, timeUnit month, 키워드 그룹 2개: [키워드 자체], [브랜드명("로담한의원")]로 검색량 추세 비교. 401/Scope 오류가 나면 네이버 개발자센터 앱에 "데이터랩(검색어트렌드)" API가 활성화되어 있는지 확인이 필요함을 사용자에게 안내하고, 안 되면 이 항목만 생략하고 계속 진행

각 결과에서 **로담한의원(또는 지점) 콘텐츠가 몇 건, 몇 위에 노출되는지** 직접 세어본다.
공식 채널(로담 공식 블로그/카페) 뿐 아니라, **일반 고객이 올린 개인 블로그/카페 후기 중
"로담한의원" 또는 지점명이 명시된 글도 동일하게 로담의 노출 성과로 집계**한다 — 개인 후기는
공식 콘텐츠보다 신뢰도가 높게 받아들여지는 채널이라 노출 성과 판단에서 제외하면 과소평가하게 됨.
집계 시 아래 두 그룹으로 나눠 표시:
- **확정 노출**: "로담한의원" 브랜드명 또는 지점명(강남/잠실/홍대신촌/노원/가산금천/수원/천안/부산/대구)이
  본문·제목에 명시된 글(공식 + 개인 후기 모두 포함)
- **추정 노출**: 브랜드명은 없지만 로담 고유 시술명("새살침", "코라테라피" 등)이 언급되고, 지역
  키워드가 로담 지점 상권과 일치하는 등 정황상 로담 관련 가능성이 있는 글 — 단, "새살침"은
  경쟁사(예: 후한의원)도 일반 시술 카테고리명으로 차용해 쓰는 경우가 있으므로(memory 경쟁사
  트래커 참고) **확정 노출과 절대 합산하지 말고 별도 항목으로 표기**하며, 원문을 직접 열람할
  수 없다면 "확인 필요"로 명시(브랜드 실수치 픽션 금지 원칙과 동일하게, 추정을 사실처럼 쓰지 않음)

등장하는 경쟁사명은 memory의 "경쟁사 트래커"(project-competitor-tracker)와 대조 —
이미 기록된 경쟁사면 재활용, 새로운 이름이면 트래커에 추가할 것을 조사 말미에 제안한다.

### 1-1. (필수) 네이버 검색광고 API — 절대 검색량
`datalab_search`는 상대지수(0~100)만 제공해 키워드 간 절대 비교가 불가능하다.
절대 월간 검색수(PC/모바일)는 **매 조사마다 반드시 포함**한다 — datalab 성공 여부와 무관하게 별도로 실행할 것.

- 스크립트: `scripts/naver_searchad.mjs` (프로젝트 루트, 이미 구현되어 있음)
- 자격증명: 프로젝트 루트 `.env.searchad` 파일(`NAVER_AD_API_KEY`, `NAVER_AD_SECRET_KEY`, `NAVER_AD_CUSTOMER_ID`) — 이미 발급·설정되어 있으므로 재발급 불필요
- 실행: `node scripts/naver_searchad.mjs "키워드1" "키워드2" ...` — 조사 키워드, 상위 개념어(예: "여드름흉터" 같은 롱테일 상위어), 브랜드명("로담한의원")을 함께 넣어 한 번에 비교
- hintKeywords 특성상 연관 키워드가 함께 반환되므로, 요청한 키워드 행만 추출해 보고서 표로 정리 (PC월간검색수 / 모바일월간검색수 / 합계 / 경쟁정도)
- 조사 키워드에 공백이 있으면(예: "편평사마귀 치료법") API가 `HTTP 400 hintKeywords 파라미터가 유효하지 않습니다` 오류를 반환함 — 공백을 제거한 형태로 재시도할 것(예: "편평사마귀치료법")
- 이 결과로 "조사 키워드 검색량 vs 브랜드명 검색량 vs 상위 개념어 검색량"을 비교해 콘텐츠 투자 우선순위(롱테일에 집중할지, 상위 개념어로 확장할지) 판단 근거로 쓴다
- 파일이 없거나 스크립트가 실패하면 그때만 datalab로 대체하고, 사용자에게 원인(자격증명 부재/스크립트 오류)을 명확히 알린다

### 2. 구글 조사 (병렬 실행)
`WebSearch` 도구를 사용한다.

- 키워드 그대로 검색 (예: `"여드름흉터제거"`) — 상위 10개 결과의 업종/도메인 구성 파악 (피부과 vs 한의원 vs 정보성 콘텐츠 vs 리뷰 플랫폼)
- `"{키워드} 병원 추천 순위 {연도}"` — 강남언니/모두닥 등 리뷰 플랫폼의 관문 여부 확인
- `"{브랜드명} {키워드} 후기 단점"` — 브랜드 자체에 대한 외부 언급/약점 파악
- 필요 시 `site:{공식도메인}` 검색으로 공식 채널의 구글 인덱스 노출 여부 확인

### 3. 갭 분석 프레임
아래 축으로 비교해 부족한 점을 정리한다 (해당 없으면 생략):

1. **채널별 노출 여부** — 공식 블로그/지점 후기가 검색되는가, 0건인 채널이 있는가
2. **경쟁사 대비 포지셔닝** — 경쟁사가 어떤 슬로건/전문성으로 상위 노출되는가
3. **카테고리 인식** — 검색결과가 특정 업종(예: 피부과)으로 이미 고착되어 있는가
4. **소비자 페인포인트 커버리지** — 카페/지식iN에서 반복되는 고민(비용, 통증, 회차, 형태 구분 등)에 브랜드 콘텐츠가 답하고 있는가. brand.md의 "타겟 고객 → 그들이 가진 문제"가 비어있다면 여기서 채울 소스로 활용
5. **리뷰 플랫폼(강남언니/모두닥 등) 등록·노출 여부**
6. **검색량 규모** (SearchAd 절대 검색량, 가능하면 datalab 추세도 함께) — 조사 키워드가 상위 개념어·브랜드명 대비 얼마나 큰 트래픽 기회인지, 콘텐츠 투자를 롱테일에 집중할지 상위어로 확장할지 판단

### 4. 출력 형식
표/불릿으로 채널별 현황 → 우선순위별 개선 제안 순으로 정리한다. 각 주장은
실제 검색에서 확인한 근거(제목/링크)를 달아 뒷받침한다. WebSearch 결과는
반드시 Sources 섹션에 링크를 포함한다 (도구 정책).

### 5. 파일로 저장
조사 결과는 사용자 응답 텍스트로도 요약하되, 전체 리포트를 `outputs/`
폴더(저장소 루트 기준, 없으면 생성)에 마크다운 파일로 저장한다.

- 파일명: `outputs/{키워드}_{YYYYMMDD}.md` (키워드에 공백/특수문자가 있으면
  언더스코어로 치환). 예: `outputs/여드름흉터제거_20260823.md`
- 같은 키워드로 같은 날 재조사하면 기존 파일을 덮어쓴다(같은 파일명이면 Edit,
  다른 날짜면 새 파일).
- 파일 상단에 조사일자, 키워드, 대상 브랜드를 명시하고, 이후 네이버/구글
  섹션과 갭 분석, Sources를 포함한다.

### 5-1. (필수) HTML 리포트도 항상 함께 생성
MD를 저장한 뒤 **매번 예외 없이** 같은 내용을 가독성 있는 HTML로도 만든다.
새로 디자인하지 말고 `assets/report-template.html`(이 스킬 폴더 내)을 그대로 재사용한다.

- 템플릿을 읽어 `{{TITLE}}`(키워드) · `{{DATE}}` · `{{KEYWORD}}` · `{{DATE_COMPACT}}`(YYYYMMDD)
  · `{{LEDE}}`(리포트 핵심 발견을 1~2문장으로 요약) · `{{BODY}}`(MD의 1~5절+Sources를
  템플릿 주석에 적힌 컴포넌트 — `stat-line`/`table-scroll`/`callout`/`priority-list`/
  `sources`—로 옮긴 HTML)를 채워 넣는다.
- 팔레트(paper/jade/clay)·타이포(Noto Serif KR/Noto Sans KR/JetBrains Mono)·톤 앤 매너는
  리포트마다 절대 바꾸지 않는다 — 여러 조사 리포트를 나중에 나란히 볼 때 동일한 브랜드
  룩앤필이어야 하기 때문. 콘텐츠(표 행, 콜아웃 개수, 우선순위 카드 수)만 키워드에 맞게 채운다.
- 저장 경로: `outputs/{키워드}_{YYYYMMDD}.html` (MD와 동일한 베이스 이름, 확장자만 다름)
- 표에서 노출 0건/열세인 행은 `row-highlight-clay` + `badge zero`, 핵심 기회·강점 행은
  `row-highlight-jade` + `badge high`로 표시해 스캔하기 쉽게 한다.
- 부정적 신호(불만, 이탈, 노출 0건 등)는 `callout warn`, 핵심 인사이트·해석은 `callout`(기본)로 구분한다.
- 생성 후 `SendUserFile`로 `display: "render"`로 전달해 바로 확인할 수 있게 한다.

## 주의사항

- 네이버 지역검색(`search_local`)은 최대 5건만 반환됨 — 로담이 5건 안에 없다고
  "노출 0건"으로 단정하지 말고 "상위 노출 미확인"으로 표현
- 데이터랩 비율(ratio)은 상대값(최대값=100)이며 두 그룹 간 절대 검색량 비교가
  아님 — 그룹 내 추세 변화로만 해석
- 브랜드 실수치는 반올림·가공 없이 `_context/brand.md` 원문 그대로 인용
